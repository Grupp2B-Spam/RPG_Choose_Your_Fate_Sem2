One RabbitMQ broker carries both event flows. SceneUpdateQueue and ChoiceQueue are logical names in the architecture; the running demo uses the RabbitMQ queues shown below.

CONNECTIVITY

SCENE UPDATES — Mock → SceneUpdateQueue → SceneIndexer

The mock publishes through RabbitMQ's management API. SceneIndexer consumes the queue through AMQP.

PLAYER CHOICES — SceneManager → ChoiceQueue

ChoiceQueue uses the same RabbitMQ broker as scene updates; it is not a separate IP or a single named queue in this demo.

ChoiceQueue broker: rabbitmq:5672
REST & DATABASE — SceneManager ↔ MongoDB

The dashboard proxies REST calls to SceneManager; SceneManager reads the Mongo scene projection.
